# 《再翻一张》游戏策划案 v2.0

> 定位：扫雷推理 × 翻牌计分 × 肉鸽构筑。本文是目标设计稿；数值为首轮试玩基线，不代表 Unity 工程已全部实现。

## 1. 游戏概述

《再翻一张》是一款 PC 端轻量 2D 单局构筑游戏。棋盘上的每个格子都是一张牌。玩家读取已经翻开牌角落的彩色数字，推断周围地雷与核心的位置，在有限的翻牌次数和护盾内，决定先积累基础牌还是寻找核心。核心牌把已经翻开的牌、后续翻牌、宝物和倍率串成可追踪的高分结算。

单局目标是经过数关与关间商店，保留累计分数并持续扩充构筑，在最后的 Boss 关完成目标。求职 Demo 优先交付一条约 15–25 分钟、可反复游玩的三关流程；商业版本再扩展卡池、Boss、事件和流派。

一句话体验：**看懂线索，赌对翻牌顺序，让核心把一连串普通翻牌变成一次大爆分。**

## 2. 设计支柱

1. **推理有价值。** 彩色数字、已知牌组组成、标记和侦察能逐步缩小风险；不会靠连续无依据猜测推进。
2. **翻牌顺序有价值。** 同一套牌，核心早翻与晚翻、先拿分与先拿金币，应产生不同收益。
3. **核心必须爽且可解释。** 核心承担大额计分、重复触发或倍率，不只给小额被动加成。玩家能看见每个效果贡献了多少。
4. **构筑能改变玩法。** 得分、金币、信息、安全、连锁与倍率都有可延伸路线。牌可升级，宝物改变规则。
5. **信息界面轻量。** 主界面只展示正在决策所需的信息；牌组数量、卡牌细则进入牌组预览查看。

## 3. 一局流程

`开局牌组与宝物 → 第 1 关翻牌达标 → 奖励选择 → 商店 → 第 2 关 → 奖励选择 → 商店 → Boss 关 → 远征结算`

每关开始生成新棋盘，玩家此前购买和奖励获得的牌进入牌组。棋盘揭示状态和核心激活状态在关间重置，牌组、宝物、金币和累计分数保留。商店后直接进入下一关。Demo 中三关结束后给出总分、构筑与主要得分来源。

## 4. 棋盘、牌组与翻牌次数

### 4.1 棋盘

- 首局基线为 6×6，共 36 张；**36 不是永久牌组上限**。
- 后续牌组数量可因购买、删牌与奖励变化。棋盘保持 6 列，行数随本关牌组数量扩展，必要时在棋盘区域滚动；首版验证范围建议 30–42 张。
- 每关把当前牌组中的牌全部洗入棋盘。地图位置随机，但牌组构成公开，具体位置未知。
- 同种牌可以有多张，每张都独立占一个格子。已升级的具体卡牌保留等级并出现在棋盘中。
- 随机种子可复现棋盘；生成器须校验牌数、线索和入口安全性。

### 4.2 翻牌次数与护盾

- 翻牌次数是**本关剩余主动翻牌操作**，与牌组总数、未翻牌数互不相同。
- Demo 初始测试值：每关 24 次主动翻牌、3 点护盾、3 次侦察。界面图中的“16”是关卡进行中的剩余次数。
- 手动翻开一张牌消耗 1 次；侦察、标记、查看牌组不消耗；部分功能牌可返还或增加次数。
- 翻牌次数耗尽且未完成关卡目标则失败。踩雷仍消耗本次翻牌，并扣 1 点护盾；护盾归零则失败。
- 随关进入时次数、护盾与侦察恢复为该关基线，宝物可以修改基线。

### 4.3 安全入口

开局自动揭示一张安全基础牌，提供第一条线索，不消耗次数，也不计入得分、金币或核心的“此前翻牌数”。生成器确保入口附近存在至少一个可推理或可侦察的前进方向。

## 5. 扫雷线索与操作

每张**已翻开**的牌，左上角和右下角显示相同线索。线索只统计该格周围八格，不统计自身；已揭示的地雷和核心仍计入原始线索，避免数字在游玩中变化。

| 角标 | 含义 |
|---|---|
| 红色数字 | 周围有地雷、无核心；数字为雷数 |
| 绿色数字 | 周围有核心、无地雷；数字为核心数 |
| 黄色数字 | 周围既有雷又有核心；数字为两者总数 |
| 灰色 0 | 周围没有雷或核心 |

黄色 4 不告诉玩家具体是几雷几核心。侦察可以“拆分线索”，显示雷数与核心数，但不直接揭示位置。未翻牌面没有数字，不泄露牌型。线索旁配合形状与颜色，兼顾色觉辨识。

左键翻开；右键循环标记“无 → 疑似地雷 → 疑似核心 → 无”。标记只是玩家笔记。点击侦察按钮后可选未翻牌查看**牌型**，或选已翻开的黄色牌拆分数字；侦察不触发效果，也不显示未翻牌的角标。悬停已知牌展示简短规则。

生成与情报供给的体验底线：不能在玩家连续两三次只见黄色大数字、侦察又已用尽时，被迫在多个高雷概率格中纯猜。试玩中若常发生，应调整生成器、入口、侦察或功能牌，而不是单纯降低雷数。

## 6. 牌的四大类

### 6.1 基础得分牌

最常见的安全牌，负责积累与提供核心的计数基础。首版含两种：

- **星星券：** 翻开获得基础分，测试值 +10 分。
- **金币牌：** 翻开获得金币，测试值 +3 金币，本张不提供基础分。

两者都算“已翻开的基础牌”，可被收集器等核心读取。因此拿金币意味着牺牲即时得分，却可能通过后续核心追回分数。不同版本的基础牌可加入邻近奖励、颜色套组、连翻、剩余次数转分等效果。每张牌均可独立升级，升级后改变自身收益或特殊规则。

### 6.2 基础功能牌

提供信息、保护或行动资源，例如放大镜侦察一格、护盾牌补盾、时钟牌返还翻牌次数。翻开时按牌面效果执行，不默认加分。升级可增加侦察范围、返还次数或附加分数。

### 6.3 核心牌

负责构筑的主要增益与爆发。它们既是扫雷线索中“核心”的统计对象，也是重要的安全目标。每张核心可升级；同名核心允许重复，但触发次数和递归规则必须明示。

### 6.4 地雷牌

翻开造成护盾损失；部分 Boss、宝物或卡牌可以改变地雷后果。Demo 初始不把地雷设计成可稳定刷分的主流派，但系统预留“拆雷获利”“地雷转化”“以伤换分”的扩展接口。地雷不会触发安全牌收益。

## 7. 核心牌首版效果

| 核心 | 核心玩法 | 爽点反馈 |
|---|---|---|
| 收集器 | 翻开时，按此前已翻开的基础牌数量一次性加分；早翻后还能从后续基础牌积累小额收益 | 基础牌逐张连向瓶子，汇总成大数 |
| 增幅器 | 激活后提高后续安全牌收益，升级后可增加倍率或区域加成 | 每次结算时倍率数字跳升 |
| 共鸣器 | 翻开时确认附近最多两张未翻开的安全基础牌；之后翻开相邻基础牌，重新结算附近已翻开的基础牌固定贡献 | 区域牌顺序点亮，形成连锁 |
| 倍频器 | 对本次即时收益应用倍率 | 分数短暂停顿后放大 |
| 测绘器 | 提供额外侦察或更精确的线索 | 地图信息成片显现 |
| 回响器 | 每累计翻开数张基础牌，按本关基础牌数量触发阶段性加分 | 进度满格时回响爆发 |

“收集器早翻吃亏”由持续积累模式缓解，但晚翻仍应是更大的单次爆发。“共鸣器诱导玩家踩雷”通过翻开时确认附近安全基础牌解决：它给出明确可执行的下一步，不要求玩家在多雷邻域盲点。

首轮平衡参考：收集器此前基础牌每张 +10 分，后续每张 +4 蓄能；增幅器后续基础牌 +6 分；共鸣器每张相邻已翻基础牌 +15 分；倍频器 ×1.5。数值需通过试玩校准，升级效果不能只做平铺加法，至少部分升级应改变触发条件或规模。

## 8. 计分、金币与高分演出

### 8.1 账户分开

- **累计分数**跨关保留。超过当前关目标的部分也保留，不能浪费。
- **金币**独立存储，用于商店。拿金币牌时不把金币直接算进分数。
- **本次得分**是一次翻牌动作结算出的即时收益，用于反馈；本关得分可单独记录用于统计。
- 收集器蓄能等未兑现资源只属于当前关，不作为跨关累计分数；达标结算前需统一兑现并显示来源。

### 8.2 结算顺序

一张牌的规则计算遵循固定顺序：扣次数 → 翻牌 → 自身基础收益/金币 → 激活核心按队列触发 → 计算加分与倍率 → 更新累计分数/金币 → 检查护盾与关卡目标。动画读取同一份结算明细，不改变结果。共鸣重新结算只发放其规定的固定贡献，不再次触发自身或其它共鸣，避免无限循环。

### 8.3 “高分很爽”的显示位置

平时主界面极简。普通翻牌只在牌旁显示小 `+10`、右侧小型本次结算和顶部累计分数微动。达到核心连锁阈值时，短暂在棋盘与右侧之间展开计分舞台：

`基础分 40 → 核心追加 40 → 倍率 ×2 → 本次 +160`

参与的基础牌依次亮起并向核心连线；核心图标按触发顺序脉冲；最终分数成为画面最大数字，随后飞入顶部累计分数。若突破关卡目标，进度条越线并显示超额分。演出可加速/跳过，但不会挡住重要线索，也不阻塞太久。**真实数值必须由规则层生成，不能为视觉爽感写出错误算式。**

## 9. 关卡与 Boss

Demo 三关，目标使用累计分数门槛。建议测试值为第 1 关 240、第 2 关 600、终局 1050；例：第一关拿到 300 分，第二关从 300 开始推进至 600。第三关实际门槛需按试玩数据调整。

第 1 关教学与构筑起步；第 2 关要求玩家利用奖励与商店形成第一组核心协同；第三关是 Boss 关。终局 Boss 的首版规则建议为“核心破盾”：Boss 有两层封印，玩家须在本关翻开并激活两种**不同名称**的核心，同时达到累计分数目标。激活后 UI 上对应封印碎裂，提供清晰阶段反馈。Boss 棋盘生成必须保证至少两种可达核心，且侦察供给足以找寻，不允许出现构筑上无解的局。

玩家可在关间继续扩充牌组；Boss 机制不能禁用刚购买的核心，避免直接否定构筑。后续 Boss 可以分别围绕翻牌顺序、金币与分数转换、地雷风险、区域连锁设计，但 Demo 先把一个 Boss 做完整。

## 10. 关间奖励与商店

每关结束先从三个随机奖励中选一个，主要提供新核心、基础牌变体、功能牌或宝物；随后进入商店。首轮试玩可让第 1 关奖励至少出现一个倍率或信息型核心，保证玩家能看到不同路线。

商店显示五个商品位，覆盖基础牌、功能牌、核心与宝物，并提供三项服务：升级一张牌、删除一张牌、付费刷新。价格为测试值，刷新逐次涨价，以避免无限寻找最优商品。购买新牌加入当前牌组，下关棋盘随牌组数量调整；升级和删牌作用于具体卡牌。离开商店后进入下一关，不要求消费完金币。商店中仍可通过顶部牌组图标查看当前构筑。

经济基本选择：金币牌拿钱而非即时分；购买强核心可能提升后续关卡收益；升级已有核心提高稳定性；删掉低效牌提高下一次翻牌质量。地雷数量与牌组数量变化的关系应在关卡配置中明示，不能因为玩家加牌就偷偷补雷。

## 11. 宝物与流派扩展

宝物是跨关被动规则，不占棋盘格。首版可设 3–5 个宝物槽与小规模池，例如：首次踩雷免伤、每关额外一次侦察、第一张核心加倍、金币牌额外 +1 金币、未用翻牌次数转分。主界面右侧只用图标显示，悬停查看规则。

可扩展流派：

- **积累爆发：** 多张基础牌 → 收集器 → 倍频。
- **区域共鸣：** 安全探路 → 布局相邻翻牌 → 重复结算。
- **经济构筑：** 早期拿金币，商店买高阶核心/升级，后期追分。
- **信息控制：** 测绘、侦察、拆分黄数，减少无依据猜测。
- **风险收益：** 护盾与拆雷能力换取高价值危险区。

新牌效果接入统一事件与计分队列，避免为每种流派单独修改棋盘逻辑。数据记录触发来源、次数、先后顺序与可重入性；数值计算和表现动画分离。

## 12. 界面与视觉规范

### 12.1 游戏主界面

顶部窄条采用图标＋数字：关卡旗帜、累计分数/目标与细进度条、金币、**只有图标的牌组入口**、剩余翻牌次数、护盾、设置。牌组入口可用 `Tab` 打开。牌组总数不在顶部显示。左侧为棋盘；右侧依次为侦察次数、当前核心图标、宝物图标和小型本次结算。详细效果由悬停提示承担。

### 12.2 牌组预览

这里才显示牌组总数和按四类统计的数量。提供筛选、排序、滚动浏览。右侧选中牌详情只显示卡牌图像、名称、类型、等级、核心效果、数值示例与升级对比；**不显示“联动”和“获取来源”板块**。这是只读预览，关闭后返回原关卡或商店。

### 12.3 商店

沿用顶部窄条与暖白背景。商品以图像、短名称、等级、金币价格为主，悬停看细则；下方提供升级、删牌、刷新；右下角进入下一关。没有独立大段说明和装饰性店主。

### 12.4 风格与反馈

轻盈简笔画、暖白纸感背景、细深色描边、淡鼠尾草绿/珊瑚红/麦金色/粉蓝色。棋盘信息是主视觉。色彩有固定职责：红/黄/绿专属于线索含义；核心触发使用金色演出，但不改变线索语义。普通状态克制，核心高分状态短暂放大；两种状态共享同一套 UI。

## 13. 教学、无障碍与验证

首局固定种子，逐步教授：安全入口 → 线索颜色 → 标记 → 黄色拆分 → 侦察核心 → 基础牌积累 → 核心大额结算。每一步只教一个动作，可跳过。所有关键信息配图形或文字，不只靠颜色；数字、牌型和已标记状态应能在 1080p 下清楚辨认。

找 3–5 位未参与设计的玩家试玩，记录：黄色数字是否被理解、是否发生连续盲猜、收集器早翻与晚翻是否都有可接受的选择、共鸣器是否提供安全起点、高分演出是否能解释来源、玩家是否知道牌组入口和金币的用途。数值验收关注胜率、每关平均剩余次数、踩雷次数、金币花费率、核心贡献占比及不同流派的使用率。

## 14. Demo 交付范围与开发顺序

目标 Demo 包含：基础棋盘与线索、标记/侦察、四类牌、可升级卡牌、可变牌组、至少三种重点核心、一个小型宝物池、跨关累计分数、两次关间商店、三关与一个 Boss、普通/高分双层反馈、牌组预览、失败与胜利结算、种子复现和 Windows 可执行包。

完整六核心、更多基础牌和宝物、商店细经济、Boss 变体可以分阶段加入。建议开发顺序：

1. 锁定规则数据结构与统一结算明细；用固定种子验证线索和无递归触发。
2. 完成翻牌次数、金币、跨关累计分数及基础牌选择。
3. 做收集器、增幅器、共鸣器三核心，验证早翻/晚翻和安全起点。
4. 接入牌组预览、奖励、商店增删升级和可变行数棋盘。
5. 做宝物、剩余核心和 Boss，并把高分反馈绑定真实结算事件。
6. 外部试玩、调数值、打包；制作两分钟演示视频与技术说明。

技术展示重点：可复现棋盘、数据驱动的卡牌配置、稳定可追踪的效果队列、规则与动画分离、可变牌组/棋盘、以及依据试玩修复“黄色线索逼猜”和“共鸣诱导踩雷”的实例。

## 15. 当前状态与待验证问题

当前已形成主界面、商店界面和牌组预览界面的视觉设计稿，且 Unity 工程中已有一部分雷牌原型规则与 UI 代码。本文是**新版目标策划**，并不表示商店、宝物、Boss、可变牌组和全部界面已经实装。

必须在下一轮原型中验证四个关键问题：
